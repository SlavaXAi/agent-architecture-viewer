# Стартовый контракт просмотра

Адаптируй этот формат к проекту; имена ключей не являются обязательным стандартом.

В описании агента полезны `id`, `title`, `summary`, `version`, `updatedAt`, `status`, `limitation`, `nodes` и `edges`. `limitation` говорит, что ещё не реализовано или не проверено.

Блок:

- `id`: стабильный идентификатор;
- `kind`: `agent`, `tool`, `resource`, `input` или `output`;
- `title`, `subtitle`, `purpose`: короткое имя и человеческое объяснение;
- `status`: `existing` или `planned`, с пояснением, подключён ли модуль к агенту;
- `implementation`: что действительно работает;
- `steps`: внутренние шаги исполнителя с понятными названиями;
- `input`, `output`: JSON примера или ограниченные сохранённые данные;
- `decisions`: возможные следующие действия и важные условия;
- `sourceFiles`: относительные пути модулей своего проекта, без ключей и приватных файлов.

Связь содержит `from`, `to`, `kind` и `label`. `data` — основная передача данных; `tool` — вызов и обратный результат; `resource` — модель или память. Все связи ссылаются на существующие уникальные идентификаторы.

Для реального сохранённого примера отдельно укажи `kind: recorded`, дату, ссылку на исходную запись и ограничения преобразования. Не обозначай его как ответ нового агента, если новый цикл ещё не запускался.

Держи данные в одном источнике. Его контрольная сумма или версия помогает понять, когда обновился интерфейс. Не передавай клиенту необработанное содержимое среды, ключи, закрытые файлы или чужие наблюдения.

В стандартной раскладке координаты, размеры, порты и дорожки вычисляются по ролям и реальным связям через `layoutSingleAgent`. Не задавай отдельные случайные координаты для каждого примера. Для нестандартного графа `layout: 'manual'` использует координаты и порты из проекта. Персональное расположение и вид холста храни отдельно, с собственной версией формата. При обновлении схемы новые блоки получают исходные координаты; неизвестные идентификаторы и некорректные числа игнорируются. «Схема ИИ» всегда показывает описание проекта, «Мой вариант» восстанавливает личный вид без изменения исходника.

Минимальное подключение адаптера через сборщик проекта:

```js
import { createCanvas } from './interactive-canvas.js';
const nodes = description.nodes; // id, kind и данные для вашего renderNode
const edges = description.edges.map((edge, index) => ({
  id: `${edge.from}:${edge.to}:${edge.kind}:${index}`,
  kind: edge.kind, label: edge.label,
  source: { cell: edge.from }, target: { cell: edge.to },
}));
const canvas = createCanvas({
  container, nodes, edges, renderNode,
  editableLayout: false, editableConnections: false,
  onSelectNode: id => showDetails(id),
});
```

Шаблон не добавляет логических связей. При передаче результата от инструмента его выход размещается отдельно от порта вызова, чтобы стрелки не накладывались. Для нескольких агентов, связей между инструментами или более восьми инструментов нужен свой сгруппированный вид с `layout: 'manual'`.

В адаптере состояние имеет `version: 2`, `viewport: {x, y, scale}`, `positions` по стабильным `node.id` и `links` по стабильным идентификаторам связей. У связи сохраняются `source` и `target` с `cell`/`port` и массив `vertices`. Сохраняй только геометрию; данные документов, подписи и содержимое блоков остаются в описании проекта. Ручное переподключение требует существующих блоков и портов; оставленный в пустоте конец отменяется. Переключение на исходную схему не стирает личный вариант, отмена/повтор работает внутри текущего сеанса, а сброс возвращает исходное расположение и связи. Эти действия не запускают агент и не меняют его исполняемую архитектуру.
